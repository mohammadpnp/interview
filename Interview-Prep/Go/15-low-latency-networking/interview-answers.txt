پاسخ‌های کامل سوالات Low-Latency + Networking (Go)

بخش پایه

1) تفاوت TCP و UDP چیست؟
پاسخ:
- TCP اتصال‌گرا و قابل‌اعتماد (ordering/retransmission) است.
- UDP بدون اتصال و سبک‌تر است اما تضمین تحویل/ترتیب ندارد.
- انتخاب بسته به trade-off latency/correctness است.
- برای مالی/تراکنشی معمولا TCP، برای telemetry/realtime خاص ممکن است UDP.

2) چرا keepalive مهم است؟
پاسخ:
- از ساخت اتصال جدید مکرر جلوگیری می‌کند.
- latency و هزینه handshake را کم می‌کند.
- اتصال مرده را سریع‌تر تشخیص می‌دهد.
- تنظیم نادرست keepalive می‌تواند منابع را هدر دهد.

3) WebSocket چه زمانی بهتر از HTTP polling است؟
پاسخ:
- وقتی push واقعی و latency پایین لازم است.
- polling در نرخ بالا هزینه شبکه/سرور را زیاد می‌کند.
- WebSocket برای اعلان لحظه‌ای، تیک قیمت، چت مناسب است.
- مدیریت connection lifecycle و backpressure ضروری است.

بخش متوسط

1) چگونه latency p95 را کاهش می‌دهی؟
پاسخ:
- مسیرهای کند غالب را با tracing/pprof پیدا می‌کنم.
- round-tripهای شبکه را کم می‌کنم (batching, caching, co-location).
- query/index و connection pool را optimize می‌کنم.
- timeoutها و concurrency limitهای درست اعمال می‌کنم.

2) connection pool اشتباه چه آسیبی می‌زند؟
پاسخ:
- pool کوچک: queue/wait زیاد و timeout.
- pool خیلی بزرگ: overload روی DB و contention.
- leak connection باعث exhaustion سریع می‌شود.
- metricهای pool (in-use, wait count) باید مانیتور شوند.

3) چه زمانی gRPC stream را انتخاب می‌کنی؟
پاسخ:
- وقتی تبادل پیوسته پیام و latency پایین لازم است.
- realtime feed یا long-lived session.
- اگر الگوی request/response ساده است، unary بهتر و کم‌پیچیدگی‌تر است.
- مدیریت flow control و cancellation در stream کلیدی است.

4) backpressure را چطور اعمال می‌کنی؟
پاسخ:
- queue bounded، semaphore/concurrency limit.
- reject/429 در overload به‌جای پذیرفتن بی‌نهایت.
- adaptive throttling با metric saturation.
- downstream protection با circuit breaker.

بخش پیشرفته

1) طراحی یک سرویس realtime با 100k connection همزمان را شرح بده.
پاسخ:
- ingress لایه load balancer + gateway stateless.
- session state سبک در memory + distributed store برای نیازهای لازم.
- shard بر اساس user/channel key.
- heartbeat، backpressure، autoscaling، و observability دقیق لازم است.

2) چگونه tail latency را بدون افت correctness کم می‌کنی؟
پاسخ:
- critical path کوتاه می‌کنم و callهای غیرضروری را async می‌کنم.
- hedging request فقط در مسیرهای idempotent.
- lock contention و GC spikes را کاهش می‌دهم.
- correctness guard (idempotency/validation) حفظ می‌شود.

3) در packet loss بالا چه استراتژی داری؟
پاسخ:
- تشخیص layer مشکل (شبکه/host/app) با metrics.
- tuning retry/timeout و کاهش payload.
- مسیر شبکه جایگزین یا multi-region failover در صورت نیاز.
- برای realtime، degradation کنترل‌شده به‌جای collapse کامل.

4) یک incident واقعی latency و مسیر حل آن را تحلیل کن.
پاسخ:
- نمونه: p99 ناگهانی بالا رفت، average عادی بود.
- trace نشان داد dependency جستجو گهگاهی 2s می‌دهد.
- fix: timeout کوتاه‌تر + fallback cache + query optimization.
- نتیجه: p99 پایدار شد، alert policy بازتنظیم و runbook مستند شد.
